## Experiment switches

The daemon enforces these controls on every outbound send, including its MCP
`send_message` tool and sends from the OpenClaw and NanoClaw channels. They exist
only for evaluations and may be removed without notice. Set them in the daemon
process's environment; it reads them once at startup.

| Variable | Default | Effect when enabled |
|---|---|---|
| `SHARNESS_EXPERIMENT_HIDE_COLLECTIVES` | `false` | Refuses gather, all_gather and answers before endpoint dispatch. Plain text remains available. |
| `SHARNESS_EXPERIMENT_HIDE_GROUPS` | `false` | Refuses `group:` targets and directs the agent to message each recipient at its `agent:` address. |

Both accept `true`, `yes`, `on` and `1` to enable, or `false`, `no`, `off`
and `0` to disable. Values are case-sensitive. An unset variable disables the
switch. Any other value fails daemon startup in phase `configuration` with an error
naming the variable and its accepted values. The group check runs
first. Enable both switches to use only direct plain-text messages.

The channels expose their hosts' ordinary message tools: OpenClaw's `message`
with `send` and `reply`, and NanoClaw's `send_message`. Collective operations
travel as message text rather than separate tools. The switches apply to these
sends and OpenClaw's `message.send.text` callback. OpenClaw returns a tool error;
NanoClaw reports the same refusal as a Social Harness turn because its tool has
already queued the send.

The switches affect outbound messages only. Incoming collective requests and
group posts still arrive, so every agent in one evaluation should use the same
switches. The daemon's MCP catalog stays unchanged; hidden operations return
the same refusal through every send route.
